- ✅ MH3G 修改器 `v1.3.0-beta.2` 已接入大厅、邮箱账号中心、昵称、发布、查重、点赞、举报和一键加入装备箱。
- ✅ Admin 已覆盖用户、角色、公开配装、举报和审计管理；生产环境已启用 HTTPS、资源限制和每日备份。
- ✅ 邮箱注册、邮箱验证、邮箱登录、绑定邮箱、密码找回、邮件配置和发送记录已经完成并上线。

生产入口为 `mhed.web.65h26i.top`、`mhed.api.65h26i.top`、`mhed.admin.65h26i.top` 和
`mhed.desk.65h26i.top`。AOKSend 密钥和模板由超级管理员在生产 Admin 中配置并启用。

## 目标与当前顺序

平台优先验证最核心的用户闭环：

```text
公开配装大厅
→ 修改器筛选和查看
→ 导入本地配装器重新计算
→ 一键加入当前装备箱
→ 登录后举报和管理员处置
→ 后台创建用户及登录
→ 用户发布、删除和点赞
→ 邮箱注册、验证和找回密码
```

公开浏览、筛选、详情和导入不要求登录。登录系统、公开注册和邮件服务不能成为第一版大厅的
前置条件。

## 固定产品边界

- 服务器只接收标准化 `MH_LOADOUT` 逻辑数据，不接收完整存档、角色名、原始装备字节或
  平台偏移。
- 服务器摘要只用于列表和筛选；修改器导入后必须使用当前本地游戏数据库重新计算技能、属性
  和风险。
- 不自然护石、孔位超限等游戏合法性问题继续只作提示。只有协议损坏、数值越界、未知游戏、
  无法解析的 ID 或不兼容数据版本可以阻止导入和写入。
- 所有游戏按 `game + schema_version + data_version` 隔离。不得跨游戏偏移 ID 或按名称猜测
  替换装备。
- 第一版不做图片、头像、附件、私信、关注、评论、推荐算法、自动配装或付费内容审核。

## 阶段一：冻结交换协议与游戏适配器（已完成）

### 交换协议

以 MH3G 修改器当前已经通过回归的 `.mhloadout.json` 为 `MH_LOADOUT` v1 基础：

- 装饰珠保存在武器、防具和护石各自的 `decorations` 中，不再增加另一份顶层装饰珠数据。
- 技能合计、防御、耐性、合法性和点赞数不是权威字段，不进入可导入的规范载荷。
- `data_version` 使用游戏数据 manifest 哈希；服务器保存并原样返回。
- JSON 使用稳定字段、整数边界和明确的 `null` 规则；未知字段策略在协议冻结时固定。

在 `contracts/` 中同时维护：

- HTTP OpenAPI 3.1。
- `MH_LOADOUT` JSON Schema。
- 成功、非法但可用、结构损坏、数据版本不兼容等跨实现测试夹具。

### 服务端游戏适配器

API 镜像按版本携带只读游戏 SQLite 和 manifest。首个 `mh3g` 适配器负责：

1. 校验协议与所有整数边界。
2. 解析真实 `save_type + save_id`、护石和装饰珠。
3. 重新计算发动技能、装备索引和风险摘要。
4. 生成用于 PostgreSQL 查询的关系型索引。
5. 对同一载荷生成稳定的内容哈希，支持去重和举报快照。

服务端与 Qt 计算器必须使用同一组夹具验证结果，不能信任客户端上传的技能摘要。

### 验收

- 当前 MH3G 本地 JSON 全量往返不改变逻辑值。
- Go 与 Qt 对自然配装、不自然护石、超孔和胴系统倍加的计算结果一致。
- 修正游戏数据后，旧 `data_version` 不会被静默解释成新含义。

## 阶段二：公开配装大厅与修改器导入（已完成）

### PostgreSQL 数据

首批迁移只建立大厅必需的数据：

- `loadouts`：游戏、数据版本、名称、备注、规范 JSONB、内容哈希、状态、发布时间。
- `loadout_equipment_index`：槽位、装备类型和真实存档 ID。
- `loadout_skill_index`：技能系、点数和发动技能 ID。
- `loadout_reports`：匿名或登录举报、原因、证据快照和处理状态。
- `admin_audit_logs`：隐藏、恢复、忽略举报和软删除操作。

配装状态至少区分 `published`、`hidden` 和 `deleted`。公开查询固定只返回 `published`。

登录功能完成前，测试配装通过版本化 seed 或仅能在服务器本地执行的管理命令导入。不得为了
跳过账号开发而暴露无认证的新增、删除或审核接口。

### 公开 API

桌面入口统一使用 HTTPS JSON 和游标分页：

```text
GET  /v1/desktop/loadouts              # 支持 legal_only=true 只看服务端判定为合法的配装
GET  /v1/desktop/loadouts/{id}
POST /v1/desktop/loadouts               # 登录后上传；按去除名称、规范化珠子顺序的 build_hash 查重
POST /v1/desktop/loadouts/{id}/likes    # 登录用户点赞
DELETE /v1/desktop/loadouts/{id}/likes  # 取消点赞
POST /v1/desktop/loadouts/{id}/reports  # 登录用户举报
```

列表查询支持：

- 必填游戏；首版为 `mh3g`。
- 套装名、备注的关键词搜索。
- 多个装备条件，全部使用 AND。
- 多个发动技能条件，全部使用 AND。
- 最新发布和点赞最多排序。
- 稳定游标分页；不使用会随新增记录漂移的深页码。

响应必须有稳定错误码、请求 ID、超时和重试边界。列表只返回轻量摘要；详情才返回完整规范
配装和风险摘要。

### 修改器配装大厅

MH3G 修改器新增独立“配装大厅”页面：

- 未登录、未读取存档时也可浏览、筛选和查看详情。
- 名称型装备和技能筛选统一使用项目既有的可搜索输入选择组件。
- 网络请求异步执行，提供加载、空结果、超时、离线和重试状态，不阻塞 Qt 主线程。
- 详情导入先完整解析到临时 `LoadoutModel`，失败时当前本地配装保持逐字段不变。
- 导入成功后用本地 SQLite 和 `LoadoutCalculator` 重新计算，不采用服务器摘要作为权威。
- 有当前存档时可调用既有事务式 `LoadoutSaveBridge` 一键加入装备箱；无存档时只导入本地
  配装器。
- 一键加入仍不自动穿戴、不自动保存磁盘，只设置存档 dirty。

修改器不得上传存档路径、角色信息、装备箱内容或任何原始存档字节。在线服务不可用时，本地
配装、JSON 和存档编辑功能必须继续正常工作。

### 阶段验收

- 公开列表、装备 AND、技能 AND、关键词、排序和游标分页结果正确。
- 断网、DNS 失败、TLS 错误、超时、错误 JSON 和不兼容版本均不会修改本地配装或存档。
- 大厅详情导入后的技能、防御、耐性和风险与原发布端一致。
- 3DS、Wii U 真实样本一键加入仍只改变预留的七条装备箱记录。
- 列表达到一万条时，常用筛选使用索引且不进行全表 JSON 扫描。

## 阶段三：登录举报与后台处置（已完成）

### 举报

登录用户可以举报，但不能编辑或删除他人内容。固定原因包括：

- 套装名或备注不当。
- 广告或垃圾内容。
- 配装数据恶意或无法导入。
- 侵权或冒充。
- 其他原因。

举报保存当时的套装名、备注、规范载荷哈希和必要证据快照。发布者之后修改内容不能抹掉原
举报证据。

举报去重使用服务端 HMAC 后的用户 ID 摘要，不把登录用户名或原始 IP 作为公开业务字段。
初始限制为同一用户对同一配装只能保留一条待处理举报，且每小时最多五次。举报数量不会
自动下架内容，避免集中恶意举报。

### 管理处置

账号系统完成前，举报通过 SSH 下的本地 `mhedctl` 管理命令处理。命令支持：

- 查看待处理举报和证据快照。
- 隐藏配装。
- 恢复配装。
- 忽略举报。
- 软删除配装。

每项操作写入审计日志。账号登录完成后，同一能力再接入 `mhed.admin`，不得另写一套处理
规则。

### 免费文本限制

不接付费内容审核。套装名和备注只允许纯文本，输出时统一转义，不支持 HTML、Markdown、
外链、图片或附件。建议限制套装名 1～40 字符、备注最多 500 字符。

当前不接付费审核或大型违禁词库。服务端只执行纯文本长度限制、统一转义和结构校验，其他文字
问题通过用户举报与超级管理员人工处置；举报不会自动下架配装。

## 阶段四：后台创建用户与登录（已完成）

第一版账号不开放注册，由管理员创建：

- 用户名唯一，邮箱暂时可空。
- 登录用户名只用于认证；大厅只显示独立昵称和公开数字 ID。默认昵称为“用户 + 公开 ID”，用户可在修改器个人信息页修改。
- 普通用户默认不分配任何角色；“已登录用户”是账号状态，不是一个隐式角色。
- 超级管理员生成一次性临时密码。
- 密码使用 Argon2id；任何日志和数据库字段都不得保存明文密码。
- 首次登录强制修改临时密码。
- 浏览器使用同站安全 Cookie，修改器使用随机 Bearer Token；数据库只保存令牌哈希。
- 会话保存最后使用时间和撤销状态，闲置 8 小时、绝对 24 小时后失效。
- 禁用或软删除用户后立即禁止刷新会话。

### 角色与权限

PostgreSQL 增加 `roles`、`permissions`、`user_roles` 和 `role_permissions`。角色只授予额外
能力，不代替资源所有权判断：

- 初始保留角色为 `super_admin`。
- 只有 `super_admin` 可以进入 `mhed.admin`、调用 `/v1/admin/*`、创建或禁用用户、分配或
  撤销角色，以及处理配装和举报。
- 普通用户没有角色，仍可使用公开 API，并在阶段五按所有权发布、编辑和删除自己的配装。
- 需要额外授权的 API 使用明确 permission，例如 `loadout.moderate`、`loadout.feature`、
  `user.manage`、`role.manage`；路由声明所需 permission，禁止在 handler 中散落角色名称判断。
- 普通用户发布自己的配装属于阶段五定义的基础登录能力，不要求为了发布而分配角色。
- 所有角色和权限判断必须在 Go API 服务端执行。Admin 前端的路由保护和菜单隐藏只改善
  体验，不能作为授权边界。
- 未登录返回 `401`，已登录但权限不足返回 `403` 和稳定错误码。
- 角色分配、撤销、用户禁用和权限拒绝写入安全或审计日志，但不记录访问令牌。

首个 `super_admin` 只能通过服务器本地 `mhedctl` 引导创建。系统不得允许删除、禁用或撤销
最后一个可用的 `super_admin`，避免永久失去后台访问。角色变化后必须立即影响新请求，不能
仅依赖长期令牌中不可撤销的角色声明。

Admin 页面在本阶段接入用户、角色、配装和举报管理。所有管理操作写审计日志。

## 阶段五：发布、删除与点赞（已完成）

登录用户获得以下能力：

```text
POST   /v1/desktop/loadouts
DELETE /v1/desktop/loadouts/{id}
POST   /v1/desktop/loadouts/{id}/likes
DELETE /v1/desktop/loadouts/{id}/likes
```

- 服务端重新解析和索引每次发布，不接受客户端声明的技能或点赞数。
- 发布前按忽略套装名、备注并规范化装饰珠顺序的 `build_hash` 查重；相同内容返回 `DUPLICATE_LOADOUT`。
- 只有所有者可以软删除自己的配装；管理员使用独立审核权限。
- 删除默认软删除，详情和索引在保留期内可审计。
- `loadout_likes` 使用 `(user_id, loadout_id)` 唯一约束，点赞数由数据库事务维护。
- 发布和点赞分别限流；异常点赞可在后台查看和清理。
- 文本限制、举报和隐藏机制沿用阶段三，不因登录而绕过。

## 阶段六：邮箱注册与验证（已完成）

最后接入公开注册：

- 用户名、唯一邮箱和密码注册。
- 邮箱验证码、重发限制、有效期和尝试次数。
- 忘记密码、重置密码以及所有设备会话撤销。
- 邮件通过可替换 Provider 接口发送，首个实现为 AOKSend API v2。
- 使用 PostgreSQL Outbox 和后台 worker 保证可重试，不引入 Redis 或消息队列。
- Admin 系统设置页保存加密 API 密钥、模板 ID、发件人别名和回复地址，并提供余额查询与测试发送。
- Desk 个人信息页提供登录/注册、邮箱绑定、忘记密码、昵称管理、退出和当前公开配装获赞数。

AOKSend 官方文档：

- 发送邮件：<https://www.aoksend.com/api.html>
- 查询余额：<https://www.aoksend.com/check_balance_api.html>

首版不启用图形验证码。验证码有效期、尝试次数、邮箱/IP 重发频率及 Nginx 基础限流均已启用；
发现真实滥用后再增加图形验证码或更严格限制。

## 部署与资源边界

4核4G 服务器使用均衡 Compose 限制：API 1.25 CPU / 640 MiB，PostgreSQL 0.75 CPU /
640 MiB，静态前端 0.20 CPU / 128 MiB，备份 0.10 CPU / 96 MiB。PostgreSQL 不映射公网端口，
API、Web 和 Admin 只绑定宿主机回环地址，由 Nginx 在 80/443 提供四个域名入口。

后续升级服务器时只扩大资源限制和连接池，不更换数据库或拆分服务。Redis、搜索引擎、
对象存储、CDN 和消息队列必须有真实负载证据后才能引入。

## 跨阶段质量门槛

每一阶段都必须满足：

- OpenAPI、迁移、服务端实现和客户端调用在同一变更中更新。
- Go 单元/集成测试、前端类型检查与构建、Compose 校验和 GitHub CI 通过。
- 数据库迁移只追加，不修改已部署迁移；失败可回滚且不会留下半写入索引。
- 所有外部输入有长度、类型、整数边界和枚举校验，SQL 固定参数化。
- 日志不记录密码、令牌、验证码、完整配装备注中的敏感文本或存档相关数据。
- 管理操作、举报处置和内容状态变化可审计。
- 备份恢复演练完成前不接受真实用户账号。
